# Database Browser

Реализованы подключение SQLite-базы (UC-01), изменение сохранённого подключения (UC-16), его удаление (UC-17), создание (UC-06) и удаление индексов (UC-08).

Профили сохраняются между запусками. При открытии проверяются заголовок файла и целостность базы. Удаляется только профиль, сам файл БД остаётся. Во вкладке Schema можно просматривать, создавать и удалять индексы. SQL Editor и Query Plan пока отключены.

## Установка и запуск

Нужен Python 3.14. Также поддерживается 3.12. Команды ниже — для Git Bash на Windows, из корня проекта:

```bash
py -3.14 -m venv .venv314
./.venv314/Scripts/python.exe -m pip install -r requirements-dev.txt
./.venv314/Scripts/python.exe -m pip install -e . --no-deps
./.venv314/Scripts/python.exe -m database_browser
```

Для 3.12 замените `3.14` на `3.12`, а `.venv314` на `.venv312`. В PyCharm нужно выбрать Python из созданного окружения.

Небольшую базу для проверки можно создать командой:

```bash
./.venv314/Scripts/python.exe examples/create_demo.py
```

После этого в приложении выбрать `demo.sqlite3` через Open database.

## Тесты

```bash
./.venv314/Scripts/python.exe -m pytest -q
```

Проверяются реальные временные SQLite-базы, ошибки, отмена действий, сохранность файлов и формы Qt. Подробности проверок есть в `TESTING.md`.

## Файлы проекта

- `models.py` — профиль и данные текущего подключения.
- `repositories.py` — чтение и сохранение профилей.
- `query_executor.py` — проверка, открытие и закрытие SQLite-файла.
- `services.py` — логика трёх юзкейсов.
- `background.py` — очередь операций в одном потоке.
- `controller.py` — связь фоновых операций с интерфейсом.
- `ui.py` — главное окно и формы.
- `app.py` — создание и запуск приложения.
- `schema/` — модели индексов, SQLite-репозиторий, логика и интерфейс вкладки Schema.

## Индексы

Откройте БД во вкладке Database, затем перейдите в Schema и нажмите Create index. Выберите таблицу, имя и столбцы. Порядок выбранных столбцов меняется кнопками Up/Down, направление — ASC/DESC. Флажок UNIQUE запрещает повторяющиеся ключи. Справа показывается SQL, который будет выполнен.

При ошибке форма остаётся открытой с введёнными параметрами. При отмене база не меняется. После успешного создания список обновляется. Для подключения только для чтения доступен просмотр.

Для удаления выберите пользовательский индекс и нажмите Delete index. Подтверждение показывает связанную таблицу. Удаление сохраняет таблицу и её строки; индексы ограничений удалить этой кнопкой нельзя. Пользовательский UNIQUE-индекс удаляется так же, как обычный.

Редактор работает с основной схемой `main` и обычными таблицами, включая generated-столбцы. Индексы выражений, partial-индексы и индексы с нестандартной COLLATE видны с исходным SQL, но упрощённая форма не должна переписывать их определение. Индексы ограничений PRIMARY KEY/UNIQUE изменяются через структуру таблицы (UC-04).

Операции выполняются в фоновом потоке. Собственный SAVEPOINT позволяет откатить ошибку, не завершая чужую транзакцию. Если внешняя транзакция уже открыта, изменения индекса станут постоянными только после её COMMIT.

## Как хранятся подключения

Профили лежат в отдельной базе `settings.sqlite3` в пользовательской папке приложения. Чтобы хранить их рядом с проектом:

```bash
./.venv314/Scripts/python.exe -m database_browser --data-dir ./local-data
```

Служебную базу нельзя открыть как пользовательскую. Отсутствующий файл автоматически не создаётся. Если запись недоступна, выполняется попытка открыть базу только для чтения. Пустой файл без SQLite-заголовка не принимается как готовая база.

При редактировании профиля текущая сессия остаётся на старом файле до переподключения. Если файл не прошёл проверку или параметры не сохранились, прежнее соединение остаётся открытым. Если при переключении не удалось закрыть старую базу, уже сохранённый новый профиль остаётся в списке.

При удалении сначала закрывается соединение, затем удаляется запись. Поэтому при ошибке удаления профиль может остаться в списке уже отключённым. Незавершённую транзакцию нужно подтвердить или откатить до закрытия соединения.

## Подключение остальных модулей

Все операции с открытой базой выполняются через `ConnectionController.submit_database_operation(name, operation)`. Внутри переданной функции доступен `manager.executor.connection`. Там можно создать репозиторий индексов или другого модуля.

Соединение и курсоры нельзя передавать в UI или другой поток. Результат возвращается сигналом `operation_result(name, result)`; обработчик в UI обновляет нужную вкладку. Каждый новый модуль должен сам определить, когда подтверждать или откатывать свои изменения.

Сборки `.exe` и ограничения CPU до 30% пока нет.
