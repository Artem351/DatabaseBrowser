# Database Browser

Реализованы подключение SQLite-базы (UC-01), изменение сохранённого подключения (UC-16), его удаление (UC-17), создание (UC-06), удаление (UC-08) и изменение индексов (UC-07), создание (UC-03), изменение (UC-04) и удаление таблиц (UC-05), выполнение SQL (UC-13) и просмотр больших результатов порциями (UC-14).

Профили сохраняются между запусками. При открытии проверяются заголовок файла и целостность базы. Удаляется только профиль, сам файл БД остаётся. Во вкладке Schema можно просматривать, создавать, изменять и удалять индексы. SQL Editor и Query Plan пока отключены.

## Установка и запуск

Нужен Python 3.14. Также поддерживается 3.12 и 3.11. Команды ниже — для Git Bash на Windows, из корня проекта:

```bash
py -3.14 -m venv .venv314
./.venv314/Scripts/python.exe -m pip install -r requirements-dev.txt
./.venv314/Scripts/python.exe -m pip install -e . --no-deps
./.venv314/Scripts/python.exe -m database_browser
```

Для 3.12 замените `3.14` на `3.12`, а `.venv314` на `.venv312`. С 3.11, аналогично. В PyCharm нужно выбрать Python из созданного окружения.

Небольшую базу для проверки можно создать командой:

```bash
./.venv314/Scripts/python.exe examples/create_demo.py
```

После этого в приложении выбрать `demo.sqlite3` через Open database.

## Таблицы (UC-03, UC-04, UC-05)

Вкладка **Schema** состоит из двух разделов: **Tables** и **Indexes**.

- **Create table…** (UC-03): имя, столбцы (тип, PK, NOT NULL, UNIQUE, AUTOINCREMENT, значение по умолчанию) и ограничения таблицы (составные PRIMARY KEY/UNIQUE, FOREIGN KEY с ON DELETE/ON UPDATE, CHECK). Под формой показан SQL. Ошибка SQLite выводится в форме, введённые данные не теряются.
- **Edit table…** (UC-04): столбцы можно добавлять, переименовывать, удалять, менять тип и признаки; ограничения можно добавлять и удалять. Таблица пересоздаётся по рекомендованной процедуре SQLite с копированием строк в одном savepoint: изменение применяется целиком или не применяется вообще. Сохраняются индексы, триггеры, значения rowid, счётчик AUTOINCREMENT, представления и внешние ключи дочерних таблиц (их строки не удаляются каскадом). Имя таблицы не меняется.
- **Delete table…** (UC-05): подтверждение с предупреждением; если на таблицу ссылаются внешние ключи, перечисляются ссылающиеся таблицы (ON DELETE CASCADE удалит их строки, а без каскада SQLite откажет, и всё останется как было).

Ограничения формы. Таблицы с COLLATE, именованными ограничениями (CONSTRAINT), ON CONFLICT, DEFERRABLE, MATCH, generated-столбцами, WITHOUT ROWID и STRICT показываются как «view only»: их можно просматривать и удалять, но не изменять, чтобы форма не меняла их смысл молча. Столбцовые CHECK и REFERENCES показываются как ограничения таблицы (по смыслу они эквивалентны). Для таблицы, у которой есть внешние ключи или на которую они ссылаются, перестройка внутри незавершённой пользовательской транзакции отклоняется: SQLite не позволяет отключить внешние ключи внутри транзакции, а удаление старой таблицы выполнило бы ON DELETE-действия. Сначала нужно зафиксировать или откатить транзакцию.

Код: `schema/table_models.py`, `table_parser.py`, `table_sql.py`, `table_repository.py` (`SQLiteTableRepository`), `table_services.py` (`TableManager`), `table_ui.py`.

## Индексы

Откройте БД во вкладке Database, затем перейдите в Schema и нажмите Create index. Выберите таблицу, имя и столбцы. Порядок выбранных столбцов меняется кнопками Up/Down, направление — ASC/DESC. Флажок UNIQUE запрещает повторяющиеся ключи. Справа показывается SQL, который будет выполнен.

При ошибке форма остаётся открытой с введёнными параметрами. При отмене база не меняется. После успешного создания список обновляется. Для подключения только для чтения доступен просмотр.

Для удаления выберите пользовательский индекс и нажмите Delete index. Подтверждение показывает связанную таблицу. Удаление сохраняет таблицу и её строки; индексы ограничений удалить этой кнопкой нельзя. Пользовательский UNIQUE-индекс удаляется так же, как обычный.

Для изменения нажмите Edit index. Форма показывает текущие столбцы и UNIQUE; имя и таблица остаются прежними. Замена выполняется целиком: если новое определение нельзя создать, восстанавливается старое. Введённые изменения остаются в форме для исправления.

Редактор работает с основной схемой `main` и обычными таблицами, включая generated-столбцы. Индексы выражений, partial-индексы и индексы с явной COLLATE или сравнением, отличным от BINARY, можно просматривать и удалять, но не менять простой формой. Это сохраняет их исходную семантику. Индексы ограничений PRIMARY KEY/UNIQUE изменяются через структуру таблицы (UC-04).

Операции выполняются в фоновом потоке. Собственный SAVEPOINT позволяет откатить ошибку, не завершая чужую транзакцию. Если внешняя транзакция уже открыта, изменения индекса станут постоянными только после её COMMIT.

Для проверки индексов есть отдельный пример:

```bash
./.venv314/Scripts/python.exe examples/create_index_demo.py
```

Откройте `index_demo.sqlite3`. Попробуйте изменить `ix_books_genre` на UNIQUE: повторяющиеся жанры приведут к ошибке, прежний индекс останется. Скрипт не перезаписывает уже существующий файл.

## Как хранятся подключения

Профили лежат в отдельной базе `settings.sqlite3` в пользовательской папке приложения. Чтобы хранить их рядом с проектом:

```bash
./.venv314/Scripts/python.exe -m database_browser --data-dir ./local-data
```

Служебную базу нельзя открыть как пользовательскую. Отсутствующий файл автоматически не создаётся. Если запись недоступна, выполняется попытка открыть базу только для чтения. Пустой файл без SQLite-заголовка не принимается как готовая база.

При редактировании профиля текущая сессия остаётся на старом файле до переподключения. Если файл не прошёл проверку или параметры не сохранились, прежнее соединение остаётся открытым. Если при переключении не удалось закрыть старую базу, уже сохранённый новый профиль остаётся в списке.

При удалении сначала закрывается соединение, затем удаляется запись. Поэтому при ошибке удаления профиль может остаться в списке уже отключённым. Незавершённую транзакцию нужно подтвердить или откатить до закрытия соединения.

## SQL Editor (UC-13, UC-14)

После подключения базы откройте вкладку **SQL Editor**. Введите один SQL-запрос и нажмите **Run SQL** или **Ctrl+Enter**. Выполняются SELECT, INSERT, UPDATE, DELETE, DDL, WITH, PRAGMA и команды транзакций. Несколько SQL-операторов за один запуск не поддерживаются: это предотвращает частичное выполнение скрипта по ошибке.

- Результат с возвращаемыми столбцами показывается в таблице, включая пустой результат, NULL и BLOB
- **Rows per batch** задаёт размер порции для следующего запроса: от 1 до 5000 строк, по умолчанию 500
- **Load next batch** читает следующую порцию из того же курсора, запрос не запускается заново при каждой загрузке
- **Stop loading** прерывает выполняющийся запрос/подсчёт либо закрывает курсор. Уже загруженные строки остаются доступны
- Показываются время выполнения, время чтения порций, число загруженных и затронутых строк, если SQLite позволяет его определить
- Для обычного SELECT отдельная фоновая задача выполняет `COUNT(*)` над результатом запроса, учитывая DISTINCT, GROUP BY, LIMIT и OFFSET. Ошибка подсчёта не скрывает таблицу и не мешает читать следующие порции
- Запросы, меняющие данные, включая `RETURNING`, не повторяются для подсчёта. Для них и запросов с `random()` и подобными функциями точный размер становится известен после полного чтения результата
- В таблице используется временный файл: в памяти остаются до четырёх порций и текущий передаваемый результат. Старые строки можно просматривать, они читаются из файла. Временный файл удаляется при закрытии приложения
- Соединение и курсор остаются в одном фоновом потоке. В UI передаются только данные. Подсчёт использует ту же очередь и соединение; пока он идёт, другие операции с БД ждут, но интерфейс и кнопка остановки работают
- Новый запрос или переподключение освобождает старый курсор. Изменение схемы через вкладку Schema также закрывает курсор, сохраняя загруженные строки в таблице
- SQL-ошибки показываются прямо под редактором, введённый текст сохраняется. Ошибка следующей порции помечает результат как неполный
- После SQL, меняющего схему, разделы Tables и Indexes обновляются автоматически

INSERT, UPDATE, DELETE и их варианты с WITH оставляют изменения в транзакции: нажмите **Commit**, чтобы сохранить, или **Roll back**, чтобы отменить. Команды BEGIN, COMMIT, ROLLBACK можно выполнять и через редактор. DDL следует правилам SQLite: вне явной транзакции изменение схемы сохраняется сразу; для возможности отката сначала выполните BEGIN. Незавершённая транзакция препятствует закрытию и переключению базы, чтобы изменения не терялись незаметно.

Остановка чтения `RETURNING` сама по себе не откатывает изменения. Прерывание исполняющегося изменяющего запроса может откатить транзакцию по правилам SQLite. Время и общее число строк — разные показатели: отдельный COUNT повторно вычисляет читающий запрос, поэтому для нестабильных функций или внешних изменений его результат может отличаться от количества строк, прочитанных курсором. После полного чтения показывается точное число полученных строк. Порционная загрузка ограничивает память приложения, но внутренние сортировки и RETURNING могут расходовать память внутри SQLite.

Для ручной проверки большой выборки можно выполнить без создания дополнительных таблиц:

```sql
WITH RECURSIVE numbers(n) AS (
    VALUES (1)
    UNION ALL
    SELECT n + 1 FROM numbers WHERE n < 10000
)
SELECT n, 'Row ' || n AS label FROM numbers;
```

Вначале появятся 500 строк и отдельно `Total rows: 10000`. Нажимайте **Load next batch** для продолжения или **Stop loading** для остановки. Для проверки ошибки выполните `SELECT * FROM missing_table`, затем корректный `SELECT 42`.

Код расположен в `src/database_browser/queries/`: `services.py` координирует юзкейсы, `result_set.py` хранит курсор и статистику, `grid.py` отвечает за дисковый кеш таблицы, `ui.py` — за вкладку SQL Editor. Существующий `QueryExecutor` владеет текущим результатом.

## Подключение остальных модулей

Все операции с открытой базой выполняются через `ConnectionController.submit_database_operation(name, operation)`. Внутри переданной функции доступен `manager.executor.connection`. Там можно создать репозиторий индексов или другого модуля.

Соединение и курсоры нельзя передавать в UI или другой поток. Результат возвращается сигналом `operation_result(name, result)`; обработчик в UI обновляет нужную вкладку. Каждый новый модуль должен сам определить, когда подтверждать или откатывать свои изменения.

Сборки `.exe` и ограничения CPU до 30% пока нет.
